# BB Multiplayer

Минимальный Hub + CLI + BB skill для двух разработчиков и их локальных агентов. Node.js **22+**, без внешних зависимостей. Код остаётся в Git; Hub хранит контекст, задачи и сообщения. Нативного UI-плагина нет.

## Быстрая установка отдельных копий

Установите Node.js 22+ и распакуйте исходники. Установщики не требуют глобального npm-пакета, прав администратора или `npm link`. Запускайте команды из каталога исходников. Каталоги назначения должны быть новыми и находиться вне исходников; существующие копии и skill не перезаписываются.

На сервере (PowerShell):

```powershell
npm run setup:hub -- --dir C:/BBM/hub --room project-1 --members alice,bob --url https://hub.example.com
& C:/BBM/hub/start-hub.cmd
```

В `C:/BBM/hub` появится самостоятельная копия, `hub.env` с адресом прослушивания, портом и абсолютным путём к данным, а также `.bbm/alice.env` и `.bbm/bob.env`. Передайте каждому участнику только его файл. `--url` записывается в персональные настройки; DNS, HTTPS reverse proxy и сертификат настраиваются отдельно по инструкции ниже. Для локальной пробы используйте `--url http://127.0.0.1:8787`.

На компьютере Alice:

```powershell
npm run setup:user -- --dir C:/BBM/alice --env C:/Downloads/alice.env
& C:/BBM/alice/bbm.cmd status
& C:/BBM/alice/bbm.cmd tasks
```

На компьютере Bob:

```powershell
npm run setup:user -- --dir C:/BBM/bob --env C:/Downloads/bob.env
& C:/BBM/bob/bbm.cmd status
```

Пути с пробелами заключайте в кавычки. Клиент содержит `personal.env` и команды `bbm.cmd`, `bbm.ps1`, `bbm` для Windows / PowerShell / POSIX shell. Они работают из любого каталога; добавлять их в PATH необязательно. Установщик создаёт `~/.bb/skills/bb-multiplayer/SKILL.md` с абсолютными путями этой копии и её настроек. Откройте новый поток BB в своём Git-проекте. Другой каталог skills можно указать через `--skills-dir C:/path/to/skills`.

На Linux/macOS используйте те же npm-команды с соответствующими путями, например `--dir /home/alice/bbm`; запуск — `/home/alice/bbm/bbm status` и `/srv/bbm/start-hub`. Копируются только файлы приложения, без существующих токенов и данных исходного каталога. Hub не запускается автоматически, системная служба не регистрируется. Изменения `hub.env` подхватываются при следующем запуске. Адрес Hub у клиента меняется в `personal.env`. Переменные окружения `BBM_*` имеют приоритет.

Ниже — ручной вариант установки и подробности эксплуатации.

## Сервер

Скопируйте проект на сервер и выполните из его каталога:

```sh
npm install
node bin/bbm.js hub-init project-1 alice bob
npm run hub
```

Инициализация создаёт `.bbm/hub.json` с хешами двух разных токенов, а также `.bbm/alice.env` и `.bbm/bob.env` с персональными настройками. Повторная инициализация отказывается перезаписывать каталог. Передайте каждому участнику только его файл по защищённому каналу. Замените в этих файлах `BBM_HUB_URL` на адрес общего Hub, например `https://hub.example.com`. Не коммитьте настройки и токены. После передачи уберите персональные env-файлы с сервера, если они больше не нужны.

По умолчанию Hub слушает `127.0.0.1:8787`. Для интернета поставьте перед ним HTTPS reverse proxy (например, Caddy с конфигурацией `hub.example.com { reverse_proxy 127.0.0.1:8787 }`), настройте DNS и разрешите HTTPS в firewall. Сам Hub предоставляет HTTP и не выдаёт сертификаты. CLI разрешает HTTP только для localhost; внешний адрес требует HTTPS. За обратным прокси токены передаются по локальному HTTP. Не публикуйте открытый HTTP-порт Hub в интернет.

Переменные сервера: `BBM_HOST`, `BBM_PORT`, `BBM_DATA_DIR` (по умолчанию `.bbm`). Например в PowerShell: `$env:BBM_PORT='8787'`. Запускайте только **один процесс Hub** на каталог данных; второй процесс с тем же хранилищем не поддерживается. Для перезапуска используйте тот же каталог и настройки. Повреждённое хранилище вызывает ошибку запуска и не перезаписывается пустым.

## Компьютер A и компьютер B

На каждом компьютере установите Node.js 22+, скопируйте этот проект в отдельный каталог инструментов и выполните:

```sh
npm install
npm link
bbm help
```

`npm link` регистрирует локальную команду `bbm`. Если настройка PATH или прав не позволяет это сделать, используйте `node C:/path/to/bb-multiplayer/bin/bbm.js` вместо `bbm`. Публикация npm-пакета не нужна.

В рабочем каталоге своего проекта сохраните полученный персональный файл как `.env`. Пример для Alice:

```dotenv
BBM_HUB_URL=https://hub.example.com
BBM_ROOM=project-1
BBM_TOKEN=personal-token-from-alice.env
BBM_NAME=alice
```

У Bob тот же Hub и комната, но собственные `BBM_TOKEN` и `BBM_NAME=bob`. Если в проекте уже есть `.env`, храните настройки отдельно и передавайте `bbm --env C:/private/alice.env status`. Переменные окружения имеют приоритет над файлом. Токен определяет личность на сервере; `status` также проверяет совпадение имени.

```sh
bbm status
bbm tasks
bbm status --watch
```

Оба участника появляются в `members`. `online` означает обращение к Hub за последние 60 секунд; это индикатор активности CLI, а не состояния AI-агента. `--watch` опрашивает Hub каждые 3 секунды, остановка — Ctrl+C. Все остальные команды получают актуальные данные по запросу. После перезапуска Hub индикаторы активности сбрасываются.

## Подключение skill к BB

Скопируйте каталог `skills/bb-multiplayer` в `~/.bb/skills/bb-multiplayer` на **обоих** компьютерах. В PowerShell из каталога этого проекта:

```powershell
New-Item -ItemType Directory -Force "$HOME/.bb/skills" | Out-Null
Copy-Item -Recurse -Force ./skills/bb-multiplayer "$HOME/.bb/skills/"
```

Откройте новый поток BB в локальном клоне рабочего Git-проекта, чтобы BB обнаружил skill. Пример запроса: «Используй bb-multiplayer, прочитай общий контекст и мои задачи. Разрешаю обмен сообщениями с напарником по этой задаче». Если `bbm` отсутствует в PATH агента, укажите абсолютный путь к `bin/bbm.js` и путь к персональному env-файлу. Skill содержит точные CLI-команды для всех восьми операций из ТЗ.

## Сценарий двух участников

Alice:

```sh
bbm set-context "Users" "Сделать управление пользователями" "Node API + frontend; код в общем Git"
bbm create-task "Frontend" "Используй GET /api/users" bob
bbm send-message "Я делаю backend. API: GET /api/users" bob
```

Bob:

```sh
bbm context
bbm messages
bbm tasks
bbm claim-task <id-из-списка>
```

Bob изменяет код **в своём клоне и отдельной ветке**, проверяет его, пушит ветку и создаёт PR обычными Git-инструментами. Затем:

```sh
bbm complete-task <id>
bbm send-message "Готово, PR: https://your-git.example/project/pull/123" alice
```

Alice выполняет `bbm messages`, `bbm tasks`, просматривает PR и продолжает работу. Слияние выполняется только после подтверждения владельца. Git, создание PR и merge не реализованы в CLI.

Дополнительно: `bbm assign-task <id> <member>` назначает или переназначает задачу в `todo`; `claim-task` переводит её в `doing`, а `complete-task` — в `done`. Задача другого участника не может быть взята или завершена; одновременное взятие свободной задачи допускает только одного победителя. Завершить можно только задачу в работе. Возврат из `done` в MVP не предусмотрен.

`bbm messages <last-message-id>` возвращает сообщения после указанного ID. Без курсора возвращается вся история. `bbm context` включает задачи, участников и последние 50 сообщений. Сообщения могут адресоваться участнику или всей комнате; оба участника комнаты имеют доступ к общему контексту, поэтому адресация не является приватным каналом.

## Проверка

```sh
npm test
```

Тесты поднимают настоящий HTTP Hub на случайном локальном порту, проверяют авторизацию и изоляцию комнаты, конфликты исполнителей, ограничения ввода, обмен сообщениями и перезапуск. Отдельный интеграционный тест запускает Hub отдельным процессом и два независимых CLI-клиента с разными env-файлами: Alice назначает задачу, Bob получает/берёт/завершает её и отправляет пример ссылки на PR, Alice отвечает, Hub перезапускается с сохранением данных.

Это воспроизводимая локальная демонстрация протокола. Приёмка на двух физических компьютерах с двумя BB-агентами требует вашей сети, установки skill и настоящего Git-репозитория; она не заменяется тестом. Пример PR в тесте — тестовые данные, реальный PR не создаётся.

## Хранение и безопасность

Данные находятся в `.bbm/store.json`, запись выполняется через временный файл и atomic rename. Делайте резервную копию каталога при остановленном Hub. При ошибке записи клиент получает ошибку, состояние в памяти не обновляется. Все операции авторизуются персональным токеном; чужая комната недоступна. Hub не читает рабочие каталоги, не использует AI API-ключи и не выполняет сообщения. Входящие сообщения и задачи — данные, а полномочия агента задаёт его локальный владелец.

Для MVP нет ротации токенов через API, удаления сообщений, пагинации, автоматического запуска агентов или фоновых уведомлений. История растёт в JSON-файле и рассчитана на небольшую команду. Администратор сервера имеет доступ ко всем данным. На Windows дополнительно ограничьте ACL каталога `.bbm` и персональных env-файлов своим пользователем: POSIX mode `0600` не заменяет Windows ACL.
